# v1.3 退役：V2 成为唯一决策路径

## 目标
消除双轨制导致的 30 个不对齐点。v1.3 从"运行/展示路径"退役，保留为"回测对照基准"。

## 核心架构决策
**GET /api/report 拆成只读市场状态**：保留温度计/估值/因子分位（前端温度计/仓位环/风险条用），删掉所有决策字段（allocations/bond_status/allocation_summary）。决策类显示统一走 V2 preview。

## 改造分 5 个工作包

### 工作包 1：后端 — GET/POST report 瘦身为市场状态
**文件**：`src/api/server.py`、`run.py`

1. **GET /api/report 删决策字段**：
   - 删 `allocations`（分配金额）→ 前端改用 preview 的 buys
   - 删 `bond_status`（国债模拟）→ 前端改用 preview 的 cash_ledger
   - 删 `allocation_summary`（分配占比）
   - 删 allocate() 调用（L395）和 BondAccumulator 模拟 deposit（L410-420）
   - 保留 `market_temp`、`assets_out`（因子值/分位/波动率）、`portfolio_risk`（组权重，但改用真实持仓算而非 total=0）、`_divergence_check`

2. **POST /api/report 同样瘦身或废弃**：
   - POST 是 useSimulate 用的（快捷分配面板），既然前端要删快捷分配面板（工作包2），POST 可直接废弃返回 410 Gone，或内部也改成只返回市场状态

3. **run.py report 改调 build_trade_plan**：
   - `run_report()` 的非 demo 分支改调 `build_trade_plan`（带 legacy_allocation_only 兜底）
   - demo 分支保留（但标注"展示用，数字不可信"）

4. **BondAccumulator 模拟流程从 API 路径移除**：
   - GET/POST report 不再调 `deposit/accrue_interest/execute`
   - 只保留 `run.py report`（流A）和回测引擎的 bond_accumulator 调用

### 工作包 2：前端 — 决策类显示统一切 V2
**文件**：`pages/AiriDashboard.tsx`、`hooks/`、`widgets/`

1. **删"快捷分配"面板**（⚙ 折叠区 + useSimulate + POST report 调用）：
   - AiriDashboard.tsx 的 handleCalculate / useSimulate / 持仓输入表
   - 顶部"本月新增资金分配"卡片的数据源已经是 preview（我之前改的），保持不变

2. **温度计/仓位环/风险条 widget 保持用 GET report**（市场状态，只读）：
   - 但移除它们的"决策语义"（如温度计 widget 的"首调用→70%"应改成纯展示温度）
   - 风险条 widget 改用 preview 的 `before.group_weights`（真实持仓），而非 GET report 的 0 权重
   - 仓位环改用 preview 的 `account_equity_ratio`

3. **ExportPanel 改用 preview 数据**：
   - 导出文本的温度计/国债叙事改用 V2 语义
   - 删"差额转入国债（组合已满）"等 v1.3 叙事

4. **useDashboardData 轮询保留**（只刷市场状态），但 activityLog 改用 preview 结果

### 工作包 3：国债真相源统一
**文件**：`src/strategy/planner.py`、`src/execution/bond_liquidity.py`

1. **确定单一真相源 = PortfolioSnapshot.bond_pool_cash**（V2 快照传入）：
   - preview/confirm 已经用 `snapshot.bond_pool_cash`，不动
   - GET report 不再返回 bond_status（工作包1已删）
   - 前端国债显示改用 preview 的 cash_ledger（bond_pool_after 等）

2. **BondAccumulator 保留但限定用途**：
   - 只在 `run.py report`（流A 真实运行）和回测引擎里用
   - API 层不再触碰
   - `bond_accumulator.json` 文件继续由流A 维护

## 不做的事（明确边界）
- **不删 allocate() 函数本身** —— 回测引擎的 V1.3 变体需要它做对照（README §5.2）
- **不删 BondAccumulator** —— 流A 和回测需要
- **不改回测引擎** —— V1.3/静态/新策略/完整四变体对照保持原样
- **不删温度计** —— 作为市场状态展示保留，只是不再用它决定权益比例（改用 V2 闸门）

## 验证标准
1. 同一持仓下，页面所有区域（温度计/分配/国债/风险/导出）数字一致或来源明确
2. GET /api/report 不再返回 allocations/bond_status
3. 前端不再有任何 v1.3 决策类显示（只有市场状态走 GET）
4. 回测 `validate.py test` 仍四策略并列通过
