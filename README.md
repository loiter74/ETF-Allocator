# ETF-Allocator 低频执行准则（V2 候选）

> 更新日期：2026-08-02
>
> 权威定位：**每月新增资金分配器＋低频风险再平衡器**
>
> 决策频率：每月一次；不盯盘、不加杠杆、不预测短期涨跌
>
> 当前状态：核心规则代码候选；科创50利润保护仅输出影子卖单

这不是“赚到多少就拍脑袋卖、跌了多少就机械补”的交易系统。日常纠偏由新增资金完成；卖出只处理三件事：战略硬上限、12 月明显漂移、科创50专属利润保护。目标是让每次操作都能回答：为什么触发、买卖多少、风险是什么、以后如何验证。

不承诺年化 10%。组合最大回撤 35% 是风险警戒线，不是自动恐慌清仓线。如果实际承受不了约 30%–35% 的阶段回撤，应先降低权益目标，而不是临时破坏规则。

## 第一章　先固定资产与口径

### 1.1 六资产战略锚点

| 资产 | 下限 | 目标 | 战略硬上限 | 角色 |
|---|---:|---:|---:|---|
| 白酒ETF | 10% | 17.5% | 25% | 价值 |
| 银行ETF | 10% | 20% | 30% | 价值/红利 |
| 红利ETF | 10% | 17.5% | 25% | 红利 |
| 沪深300ETF | 10% | 20% | 30% | CORE 宽基 |
| 科创50ETF | 5% | 10% | 15% | 成长 |
| 国债ETF＋累积池 | 10% | 15% | 20% | 防御 |

附加约束：

- 白酒＋银行＋红利合计不超过 60%；沪深300从 VALUE 拆出，独立为 CORE。
- 不设卫星仓。机器人ETF、个股等非白名单持仓只提示，不自动生成买卖单。
- 波动率下调的上限只限制新增买入；它不是卖出线。战略硬上限才是月度核心卖出线。

### 1.2 两套口径必须分开

1. **全账户口径**：全部持仓＋现金。所有权益持仓，包括非白名单，用于计算账户权益闸门。
2. **六资产受管组合口径**：只用于六资产的目标缺口、硬上限和组别约束；非白名单不参与目标缺口。
3. **国债累积池**：账户现金中的标记子账户，不是额外资产，不得重复计入总资产。
4. **防御桶**：国债ETF＋国债累积池＋归属于累积池的逆回购。
5. **权益待投现金**：已经归属于权益预算、但因交易单位或成本未成交的现金；不得自动改投国债。

账户总资产必须由系统用“份额 × 当前价格＋现金＋逆回购”复算。券商月度快照中的份额、平均成本和现金是实盘权威来源。

### 1.3 规则卡：账户口径

| 项目 | 内容 |
|---|---|
| 目的 | 防止国债池重复记账，避免未知持仓被系统假装不存在 |
| 触发 | 每次提交月度完整快照 |
| 动作 | 同时输出全账户权益/防御比例与受管组合资产/组别权重 |
| 风险 | 错误标记现金会改变闸门和缺口；因此标记现金合计不得超过账户现金 |
| 验证 | 总资产复算、交易前后权重、现金恒等式误差不超过 0.01 元 |
| 状态 | **候选正式**；旧权重输入继续存在，但只能分配新增资金、禁止卖出 |

## 第二章　每月只按一个顺序决策

用户在月末或下月操作前提交一次完整快照：

```json
{
  "snapshot_date": "2026-08-31",
  "price_date": "2026-08-31",
  "new_money": 10000,
  "account_cash": 2272,
  "bond_pool_cash": 0,
  "equity_pending_cash": 0,
  "positions": [
    {
      "asset": "科创50ETF",
      "code": "588000",
      "shares": 600,
      "price": 1.04,
      "market_value": 624,
      "average_cost": 0.80,
      "is_equity": true
    }
  ]
}
```

系统严格按下列顺序计算：

1. 校验份额、市值、现金标记和日期，复算总资产。
2. 扫描非白名单，只告警，不交易。
3. 计算机会分、趋势、温度计和风险买入上限。
4. 先检查正式卖出与科创影子卖出。
5. 如有正式卖单，只输出卖出阶段；用户回填真实成交后再重算买单。
6. 如无正式卖单，确定权益/防御预算，执行三阶段买入。
7. 按交易单位、佣金和滑点取整，输出完整现金轧差。

### 2.1 全账户权益闸门

| 全账户权益比例 | 本月新增资金权益预算 |
|---|---:|
| `< 80%` | 100% |
| `80%–90%`，含 80% 和 90% | 使用双指标温度计 |
| `> 90%` | 0%，优先补防御 |

温度计仍使用沪深300 PE 分位和全A PB 分位：双指标同档时分别给出 100% / 70% / 40% / 30% 权益比例；不一致或数据缺失时冻结上期已确认比例。不存在“三个月后自动取低值”的附加规则。

### 2.2 防御 20% 封顶

固收配额只能补到全账户防御 20%。达到 20% 后停止新增固收；穿越 20% 的余额标记为权益待投现金，不得为了“把钱花掉”而突破防御上限。

### 2.3 规则卡：战略闸门

| 项目 | 内容 |
|---|---|
| 目的 | 先修复全账户风险结构，再讨论哪个ETF更便宜 |
| 触发 | 每月快照，按 `<80%`、`80%–90%`、`>90%` 三段判断 |
| 动作 | 决定新增资金的权益/防御预算；防御最多补至 20% |
| 风险 | 小账户会因国债整手和现金标记短期偏离目标 |
| 验证 | 80%、90%、防御20%边界测试；温度计冻结的跨月状态测试 |
| 状态 | **候选正式**；阈值纳入参数锁，测试期不得更改 |

## 第三章　补仓不是“跌了就买”

补仓只看仓位缺口、最终机会分、趋势和上限，不看“我已经亏了多少”。科创50趋势 OFF 时，机会分仍按原规则乘 0.5；单纯亏损不会触发补仓。

### 3.1 三阶段买入

#### 阶段一：下限修复

- 条件：资产低于下限，且最终机会分 `≥ 0.20`。
- 动作：按各资产“距离下限的金额缺口”比例分配，最多修复到下限。
- 机会分 `< 0.20`：即使仓位很低也不机械抄底。

#### 阶段二：目标补齐

对低于目标且机会分合格的资产计算：

```text
目标缺口金额 = 目标权重 × 规划后受管资产 - 当前市值 - 本月已分配
缺口分 = 目标缺口金额 ÷ 本轮最大目标缺口金额
综合优先级 = 0.5 × 缺口分 + 0.5 × 机会分
```

按综合优先级迭代分配，最多买到目标，不允许第一名一次吞掉所有预算。

#### 阶段三：高机会扩展

- 条件：最终机会分 `≥ 0.80`。
- 动作：目标补齐后仍有权益预算，才可扩展至“目标＋2 个百分点”。
- 上限：仍受战略硬上限、风险买入上限和组别上限三者中的最严限制。

交易单位不足或自愿交易的佣金＋滑点占比过高时，订单延后，资金保留为权益待投现金。

### 3.2 规则卡：纪律补仓

| 项目 | 内容 |
|---|---|
| 目的 | 同时解决“低配不补”和“只因亏损补仓”两个行为偏差 |
| 触发 | 有权益预算，且资产满足对应阶段的仓位和机会分条件 |
| 动作 | 下限修复 → 目标补齐 → 高机会扩展，逐层执行 |
| 风险 | 机会分可能失效；所以波动风险另行限制买入上限，且不进入机会分 |
| 验证 | 0.20/0.80边界、三阶段资金归属、目标＋2pp、VALUE 60%和现金守恒 |
| 状态 | **候选正式**；不根据单次科创浮盈回吐临时改分数线 |

## 第四章　卖出必须低频、合并、有去处

### 4.1 月度战略硬上限

白酒、银行、红利、沪深300只有在受管组合权重突破战略硬上限时，才生成正式卖单；交易后目标为“战略目标＋2 个百分点”。

| 资产 | 触发 | 卖至 |
|---|---:|---:|
| 白酒ETF | `>25%` | 19.5% |
| 银行ETF | `>30%` | 22% |
| 红利ETF | `>25%` | 19.5% |
| 沪深300ETF | `>30%` | 22% |

风险控制器临时把买入上限从 25% 降到 20%，只意味着“不再买”，不意味着把已有 22% 仓位低位卖掉。

### 4.2 12 月相对软带

每年 12 月检查一次：

```text
外部软带 = 目标 × 80% ～ 目标 × 120%
交易后内部带 = 目标 × 90% ～ 目标 × 110%
```

- 低于外部带：先用新增资金和权益待投现金补至内部下界。
- 高于外部带：才允许卖至内部上界。
- 同一资产同月命中多条卖出规则，只生成一个合并订单，采用要求最低仓位的结果。
- 科创专属规则优先，避免和年度规则重复卖出。

正式卖出所得有明确去处：全账户权益 `≤90%` 时优先补低配合格核心资产；`>90%` 时优先补防御至 20%，余额留作自由现金。

### 4.3 国债原则不卖

1. 防御超配先停止累积，并把尚未成交的池内超额重新标记为权益待投现金。
2. 国债ETF仅一手时不卖，靠新增权益资金稀释。
3. 持有多手时，仅 12 月允许整手卖出；卖后防御不得低于 10%。

### 4.4 科创50利润保护：当前只做影子单

预注册参数固定为 `25% / 12% / 2个月 / 1/3`：

1. 加权平均持仓收益达到 25%，且趋势 ON：激活保护。
2. 用已确认月末后复权收盘价记录并更新高水位。
3. 高水位回撤 `≥12%` 且趋势 OFF：影子卖出可执行份额的 1/3。
4. 连续两个月趋势 OFF：优先影子降至 5%，同月跳过 1/3 单。
5. 不足一个交易单位：不输出零份额订单，保留待触发状态。
6. 只有显式确认的月度观察更新高水位；只有真实成交才关闭周期并进入冷静期。
7. 真实卖出后至少隔一个完整月，并满足连续两月趋势 ON、机会分 `≥0.50`、仓位低于目标，才允许回补。
8. 新周期必须重新从 25% 以下向上穿越，或形成高于上一周期峰值的新高，防止反复激活。

### 4.5 规则卡：低频卖出与利润保护

| 规则 | 目的 | 触发与动作 | 主要风险 | 验证指标 | 状态 |
|---|---|---|---|---|---|
| 核心硬上限 | 防止单一资产胜者集中 | 超硬上限，卖至目标＋2pp | 牛市中可能过早降仓 | 净年化、卖出次数、成本拖累 | **候选正式** |
| 年度软带 | 只处理明显漂移 | 12月越过目标80%–120%，回到90%–110% | 小账户整手误差 | 换手率、偏离持续月数 | **候选正式** |
| 国债例外 | 避免一手清空防御 | 一手冻结；多手年度整手卖且防御≥10% | 超配稀释较慢 | 防御区间、不可执行月份 | **候选正式** |
| 科创利润保护 | 防止大幅浮盈完全回吐 | +25%激活；回撤12%且OFF卖1/3；OFF两月降至5% | 样本少、震荡误触发 | Calmar、激活窗口回撤贡献、独立触发数 | **影子** |
| 回撤35%警戒 | 提醒重新评估承受力 | 只告警，不自动清仓 | 人为恐慌干预 | 警戒后规则遵守率 | **正式原则** |

## 第五章　执行、确认与上线纪律

### 5.1 每月输出必须是交易计划

完整 `TradePlan` 至少包含：

- 正式卖单、影子卖单、买单和稳定原因代码；
- 份额、参考价、预计成交价、佣金、滑点和现金影响；
- 交易前后资产权重、组别权重、全账户权益/防御比例；
- 期初现金＋新增资金＋卖出净收入－买入支出＝期末现金；
- 因交易单位或成本延后的金额及权益/国债池标记。

有正式卖单时采用两阶段执行：

```text
预览卖单 → 用户回填真实份额/成交价/佣金 → 系统重算买单 → 显式确认
```

不得用预览卖价假装已经到账。重复预览必须幂等；重复确认由 `idempotency_key` 防止重复记账。GET、报告模拟和预览接口均不得更新持仓、国债池、温度计或科创状态。

默认成本模型：双边佣金 0.03%，每笔最低 5 元，单边滑点 5bp。真实券商费率可覆盖。自愿小额交易成本过高时延后；战略硬上限和风险卖出不因成本比例延后。

### 5.2 上线门槛

四组回测必须并列披露：

1. 当前 V1.3；
2. 静态目标权重＋年度再平衡；
3. 新闸门＋三阶段补仓＋仓位带，不含利润保护；
4. 完整策略，历史模拟科创利润保护。

正式验收：

- 完整策略净年化不得比 V1.3 低超过 2 个百分点；
- Calmar 不得低于“不含利润保护”的新策略；
- 组合最大回撤不得恶化；整体影响太小时，另看科创激活窗口的组合回撤贡献是否至少降低 20%；
- 单独披露年化成本拖累、卖出次数和独立触发次数；
- 历史＋影子期少于 3 次独立触发，科创保护继续保持影子；
- 测试期参数哈希与训练期锁不一致时拒绝运行。

敏感性网格只用于看稳健性：激活 20/25/30%，回撤 10/12/15%，OFF 1/2/3 月，卖出 1/4、1/3、1/2。不得据 2022–2025 测试期挑出“最好参数”。2026 年作为持续样本外影子观察。

## 技术附录

### A. 机会分与风险分层

机会分统一为 `[0,1]`，国债为 `None`；风险不进入评分。

| 资产 | 机会分 |
|---|---|
| 白酒ETF | `1 - PE历史分位` |
| 银行ETF | `sigmoid(0.5×PB_zscore + 0.5×股息_zscore)` |
| 红利ETF | 股息率历史分位 |
| 沪深300ETF | `1 - PE历史分位` |
| 科创50ETF | 120日动量分位 × 趋势倍率；OFF 时倍率 0.5 |

分位只使用决策日可见数据，采用 expanding 窗口并截断到配置年限。价格使用后复权收盘价；估值必须满足 `publish_date ≤ decision_date`。ETF 未上市月份不得利用指数已有信号假装可以交易。

### B. 两条数据流

- **流A（运行）**：数据 → 因子 → 机会分 → 温度计/风险买入上限 → `PortfolioSnapshot` → 共享决策函数 → `TradePlan`。只执行，不调参。
- **流B（验证）**：2015–2021 训练既有可训练参数 → 写参数锁 → 2022–2025 只验不调 → 2026 样本外影子观察。

科创参数因可交易历史较短而预注册，不从短样本中寻优。运行流、API、报告和回测必须调用同一决策函数，禁止复制规则。

### C. 数据与状态

SQLite schema v4 新增：

- `portfolio_snapshot` / `portfolio_snapshot_item`：已确认月度券商快照；
- `strategy_state`：科创月频状态机；
- `trade_plan_confirmation` / `trade_fill`：幂等确认和真实成交审计。

预览只在内存副本上计算；显式确认在同一事务内保存快照、成交、响应和状态。

### D. 入口命令

```bash
# 旧权重兼容报告（仅分配，不具备盈利保护卖出能力）
python ETF-Allocator/run.py report --demo
python ETF-Allocator/run.py report --weights '{"白酒ETF":0.12}' --total 200000

# 完整快照只读交易计划
python ETF-Allocator/run.py plan --snapshot snapshot.json

# 参数训练、四策略锁定测试、预注册敏感性
python ETF-Allocator/validate.py train
python ETF-Allocator/validate.py test
python ETF-Allocator/validate.py sensitivity

# 测试
pytest ETF-Allocator/tests/ -v
```

API：

- `GET/POST /api/report`：旧报告兼容，模拟只读；
- `POST /api/trade-plan/preview`：完整快照只读预览；
- `POST /api/trade-plan/confirm`：显式确认月度观察/真实卖出并重算后续计划；
- `GET /api/history`：PIT 历史估值序列。

Dashboard 首页的“盈利收获与交易计划”使用完整快照预览，展示科创浮盈、保护高水位、趋势、正式卖单、影子卖单、买单和现金轧差；页面扫描本身不确认观察、不写策略状态，也不执行交易。

### D.1 券商截图自动填充

完整快照表单支持“截图自动填充”，但它仍遵守人工核对和显式扫描边界：

```text
券商截图（浏览器内存）
  → Tesseract.js 本地 OCR（chi_sim+eng）
  → 仅 OCR 文字发送到后端
  → DeepSeek 可选结构化 / 本地规则安全回退
  → 字段级来源、置信度和证据核对
  → 用户点击“应用到持仓快照”
  → 用户另行点击“扫描盈利与交易计划”
```

- 原图不上传后端、不发送给 DeepSeek、不写磁盘；选择截图前仍应裁掉姓名、账号等无关信息。
- Tushare/AkShare 只能提供公开行情和估值，不能取得个人账户的真实份额、券商平均成本或现金。缺失现价可用快照日可见的本地行情低置信补齐，但必须核对；行情不得覆盖份额、成本和现金。
- DeepSeek 只是不可信的文字结构化增强器。未配置 Key、HTTP 失败、空响应、坏 JSON 或校验失败时自动使用确定性本地解析器。
- 黄色、低于 75% 置信度或空白字段必须人工核对。应用草稿只改变浏览器表单，不生成交易、不确认月度观察、不写 SQLite。

服务端可选配置写入 `ETF-Allocator/.env`：

```dotenv
DEEPSEEK_API_KEY=你的服务端Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TIMEOUT_SECONDS=30
```

API Key 不返回浏览器。配置查询与文字解析接口分别为 `GET /api/portfolio-snapshot/ocr-config`、`POST /api/portfolio-snapshot/parse-text`；两者均不修改策略状态。
