## Context

系统的风险不在于缺少模块，而在于同一设计规则在数据库、CLI、回测和 API 中有不同实现。当前数据库的 DATE 列同时保存 ISO 文本与八位整数；SQLite 的类型排序使 `publish_date <= T` 失去时间语义，Pandas 又无法稳定解析混合格式。评分和约束也存在入口漂移：回测生成银行 z-score，评分器读取 percentile；CLI 和回测计算可买系数后没有传给分配器。前端则把读取报告和国债池状态变更绑定在一起，页面刷新会产生业务副作用。

设计基准为 `ds.v1.2.winner.md`。实现必须保持风险与机会评分分离、国债作为溢出吸收口、估值 expanding window 与训练/测试隔离。

现有 Dashboard 审计结果：信息架构完整，但大量等权玻璃卡片削弱了“本月该做什么”的主次关系；固定米黄色背景与暗色主题 token 冲突；紫红渐变、emoji 和重复图表造成视觉噪声；读取 hooks 有重复请求。优化稿采用审计优先、单一蓝绿色强调色、紧凑工作台布局，保留现有导航和字段语义。

## Goals / Non-Goals

**Goals:**

- 所有决策日期、交易日期和发布日期拥有唯一、可比较的 ISO 语义。
- 任意决策日只能看到 `trade_date <= T` 且 `publish_date <= T` 的估值数据。
- CLI、回测与 API 对相同输入产生相同的因子、评分、约束和分配结果。
- 回测指标正确处理月度外部现金流，并能证明测试期参数未被修改。
- 所有报告读取和模拟接口幂等。
- 以独立 HTML 展示新的信息层级、响应式布局和交互方向，用户确认前不替换 React 页面。

**Non-Goals:**

- 不重新选择资产池，不调优策略阈值，不根据测试期收益反向调参。
- 不引入新的行情供应商或在线数据库。
- 不在本变更中完成 React Dashboard 全量重写。
- 不自动执行年度卖出交易；仍只输出建议。

## Decisions

### 1. 日期在边界统一，读取层继续防御历史脏数据

新增单一 `normalize_iso_date()`，接受 `date`、`datetime`、Pandas 时间、ISO 字符串和八位数字，输出 `YYYY-MM-DD`，无效输入抛出错误。所有 CRUD 和导入路径写入前调用它。PIT 查询不依赖 SQLite 对混合类型的直接比较，而是读取候选行后在 Python 中标准化并同时过滤交易日与发布日期。

选择 Python 过滤而不是复杂 SQL `CASE`，因为数据规模很小，语义更容易测试。数据迁移完成后仍保留防御性读取，避免旧备份或外部脚本再次引入脏数据。

### 2. 数据库迁移必须可回滚

提供独立迁移脚本，默认 dry-run；应用时先创建带时间戳的数据库备份，再在单事务内规范日期、去除同日重复键并执行审计。任何无效日期或冲突无法确定时整笔回滚。

### 3. 市场数据使用明确口径

ETF 价格请求使用 `hfq`。LOF 继续使用累计净值。股息率内部单位统一为小数；边界允许供应商百分数并归一化。供应商没有真实逐行发布时间时，估值发布日期保守设为下一个自然日，不能声称当天收盘前可见。

### 4. 银行评分只接受 z-score

银行输入统一为 `pb_zscore` 与 `dividend_zscore`，按配置权重合成后进入 sigmoid。流 A、流 B 与 API 均通过同一个因子计算函数产生这些字段。分位可保留为报告解释字段，但不得作为评分输入。

### 5. 约束结果是分配器的强制输入

所有入口必须将 `buy_coefficients` 传入 `allocate()`。因子组投后上限基于组内全部当前持仓，而不是只统计本月获得分配的资产；多个组依次约束，所有溢出统一进入国债。初始建仓不允许第二轮越过单资产上限。

### 6. 温度计状态分为纯计算与显式持久化

回测继续使用进程内状态并在每次运行前重置。CLI 报告在计算前加载、计算后保存小型 JSON 状态。GET 与模拟 API 只读取状态，不保存，保证幂等。首次无历史且指标不一致时使用设计默认的 100% 权益。

### 7. 回测以单位净值收益衡量表现

每月收益定义为本月投入前组合价值除以上月投入后组合价值减一。CAGR、最大回撤、Sharpe 和 Calmar 都从这条不含外部现金流的收益序列构造单位净值，不再用 `最终市值 / 累计投入` 近似 CAGR。

训练完成后生成包含关键参数、时间范围和 SHA-256 的锁定快照。测试模式必须验证当前参数哈希与快照一致；不一致时拒绝运行并指出差异。

### 8. API 查询与执行分离

`GET /api/report` 和 `POST /api/report` 只计算结果与国债池投影，不写文件。真实月度执行仍由 CLI 流 A 完成。这样刷新、重试和前端 StrictMode 不会重复存入资金。

### 9. HTML 稿采用可信工作台而不是营销页

设计模式为 Redesign-Preserve，保留“月报、模拟、趋势”的信息架构。视觉参数为 `DESIGN_VARIANCE=5`、`MOTION_INTENSITY=3`、`VISUAL_DENSITY=7`。使用系统字体与 CSS variables，不新增前端依赖；单一冷青色强调色，卡片半径统一 14px，数字使用等宽字体。首屏先显示本月动作、数据可信度和关键约束，图表与因子证据作为第二层。

## Risks / Trade-offs

- [历史迁移改变主键文本] -> 应用前备份，事务内迁移，迁移后比较每个指数的行数、最小/最大日期和重复键。
- [供应商发布时间不是实际时间] -> 使用保守次日规则并在报告元数据标注来源，不把估计值描述成真实发布时间。
- [修复现金流指标会使历史结果明显变化] -> 保留旧指标仅用于迁移对照，不作为正式评价指标。
- [约束修复可能增加国债分配] -> 在月度结果中输出每个缩减原因和溢出金额，避免静默改变。
- [参数锁定降低临时试验便利性] -> 训练模式可重新生成快照，测试模式严格只读验证。
- [独立 HTML 与最终 React 实现可能存在差异] -> HTML 仅用于确认信息架构和视觉方向，确认后再创建单独实现任务。

## Migration Plan

1. 运行全量测试和数据库 dry-run 审计，记录基线。
2. 部署日期规范化函数、PIT 防御性读取和迁移脚本。
3. 备份数据库并执行迁移，验证计数、日期范围和未来记录数为零。
4. 统一评分、约束、温度计和 API 幂等行为。
5. 更新现金流指标与参数锁定，运行合成回测和真实数据库 train/test。
6. 生成并人工打开独立 HTML 稿，检查桌面和移动布局。

回滚时停止写入，恢复迁移前数据库备份，并回退代码变更。参数快照和温度计状态均为可删除的派生文件。

## Open Questions

- 国债 20% 目标带与温度计允许 70% 新钱进入国债存在设计冲突。本变更遵循“国债为吸收口”，不对温度计强制国债金额应用 20% 上限，并在报告中明确区分目标带与防御性溢出。
- 用户确认 HTML 后，是对现有 AiriDashboard 做定向演进，还是以新页面并行上线，留待视觉确认后决定。
