## Context

账户份额、平均成本和现金属于券商账户私有数据，公开行情源无法获取；当前完整快照表单虽然准确，但重复手填繁琐。DeepSeek 当前适合文本 JSON 结构化，不能作为本能力的图片 OCR 依赖。浏览器 OCR 可避免上传原图，并让 DeepSeek 只处理经过裁剪的文字。

## Goals / Non-Goals

**Goals:**

- 允许上传最多 3 张常见格式的券商持仓截图，并在浏览器内完成中英文 OCR。
- 用统一后端契约把 OCR 文字解析成可核对的 `PortfolioSnapshotDraft`。
- DeepSeek 不可用时仍能解析常见“资产名/代码/市值/份额/现价/成本”行。
- 任何识别错误都停留在草稿层；只有用户显式应用后才改变页面表单。

**Non-Goals:**

- 不登录券商、不抓取账户、不保存截图、不自动确认交易。
- 不把 Tushare 当作个人持仓或成本数据源。
- 不保证任意券商版式一次识别完全正确；低置信字段必须人工核对。
- 不在本变更中引入 PaddleOCR 服务或 GPU 运行环境。

## Decisions

### 1. 原图留在浏览器

前端用 Tesseract.js Web Worker 识别 `chi_sim+eng`。原图只用于本地预览和 OCR，组件卸载或删除图片时释放 Object URL；请求体只发送 OCR 文字、文件名和 OCR 平均置信度。首次使用可能下载并缓存语言模型，页面明确展示进度。

### 2. DeepSeek 只做不可信的结构化助手

后端从 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL` 读取配置，使用 JSON Output 和固定 schema 提示。响应最多重试一次；空内容、非 JSON、HTTP 错误和 schema 错误均降级到本地解析器。模型输出必须经过 Pydantic/域模型验证、资产白名单归一和数值合理性检查。

### 3. 确定性回退解析器是基础能力

解析器以行和相邻行作为证据，识别六类白名单资产及常见别名/代码，并提取份额、现价、平均成本和市值。无法可靠判断数字角色时不猜测，返回空字段和警告。现金只在带“可用/现金/余额”等标签的行中提取。

### 4. 字段级证据与来源

每个候选字段返回 `value`、`confidence`、`source`（`ocr/deepseek/local_parser/market_data/user`）和短证据。前端把低于 0.75 的字段标黄，并允许编辑。最终应用时只复制已存在且数值非负的字段；不自动触发 `/api/trade-plan/preview`。

### 5. 行情只补现价

服务端可从 `etf_price` 查询 `price_date <= snapshot_date` 的最近后复权价，仅在现价缺失时补齐并标记 `market_data`。份额、平均成本和现金永不由行情源推断。若最新可见价格日期早于快照日，返回日期警告。

### 6. 只读、有限和不记录敏感正文

配置 GET 只返回能力、模型名和限制，不返回 Key。解析 POST 限制最多 3 段、单段 30,000 字符、合计 60,000 字符；应用日志不记录 OCR 正文或模型完整响应。接口不访问策略 repository，不写 SQLite。

## Risks / Trade-offs

- 浏览器 OCR 首次加载中文模型较慢：展示分文件进度并缓存 worker 语言数据；保留粘贴 OCR 文字的降级入口。
- 券商版式差异导致错列：字段证据、低置信高亮和显式应用将错误限制在草稿阶段。
- DeepSeek 输出可能漂移：固定 JSON schema、严格后验证和确定性回退保证接口稳定。
- OCR 文本仍可能含账号信息：上传区提示先裁剪姓名/账号；服务端不持久化也不记录正文。

## Migration Plan

1. 先上线只读配置/解析 API 和本地解析器测试。
2. 接入前端 OCR、核对与应用，不改变原手填和交易计划接口。
3. 配置 DeepSeek Key 后启用增强解析；未配置时页面明确显示本地模式。
4. 通过浏览器最新数据 QA 后更新 README/架构地图。
