## Context

见 `proposal.md`。当前流 A 接受权重和总资产后只分配新增资金；年度 checker 不持有真实份额和成本，回测也只有买入现金流。SQLite 已有估值、价格、因子和现金投入记录，但没有可作为券商月度权威输入的持仓快照或科创状态。必须继续遵守 PIT、后复权、风险与机会分分离、配置集中和测试期锁定。

## Goals / Non-Goals

**Goals:**

- 一个纯决策入口同时服务 CLI、API、报告和回测。
- 在同一现金账本上表达正式卖单、影子卖单、买单和交易前后暴露。
- 保留 V1.3 兼容输入，并让缺失份额/成本的能力降级显式可见。
- 通过确认命令而非预览更新月度策略状态，保证可重放和幂等。

**Non-Goals:**

- 不做盘中监控、预测涨跌、杠杆、税务优化或非白名单自动处置。
- 不在本变更中根据 2022–2025 测试结果调利润保护参数。
- 不承诺目标年化收益，也不把 35% 回撤警戒变为自动清仓。

## Decisions

### 1. 共享纯决策内核与显式上下文

新增策略域模型，决策函数输入完整快照、机会分、风险买入上限、温度计结果、持久化状态的只读副本和策略配置，输出不可变交易计划及“确认后状态补丁”。CLI/API/回测只能做适配，不得复制规则。相比继续扩展 allocation 和 checker 两套接口，这能让现金守恒和优先级只验证一次。

### 2. 双资产口径

全账户口径用于权益闸门和防御比例；六资产受管组合口径用于目标缺口、硬上限和组约束。账户现金只计一次，`bond_pool_cash` 是现金中的标记金额；`equity_pending_cash` 同样是标记，不创造资产。相比把未知持仓排除总资产，该口径不会低估真实风险。

### 3. 先卖后买的两阶段计划

第一阶段按快照生成正式卖单和影子卖单；存在正式卖单时买单标记为待重算。确认接口接收实际份额、价格和费用，用成交后的派生快照调用同一决策函数生成第二阶段买单。无正式卖单时可直接生成买单。这样不会用假设卖价透支，也能明确影子订单永远不进入现金账本。

### 4. 基于金额缺口的三阶段分配

每个阶段都重新计算缺口与约束：先按下限金额缺口比例分预算，再按 `0.5×相对目标缺口+0.5×机会分` 迭代到目标，最后把剩余预算仅分给分数至少 0.80 的资产并限制到目标+2pp。买单在费用和交易单位取整后再次校验现金与上限。相比一次排序后顺序灌满，该方法避免第一名独占预算并能解释每一元资金所属阶段。

### 5. 静态卖出上限与动态买入上限分离

战略硬上限只来自资产配置表；风险控制器下调的上限只参与买入容量计算。月度硬上限、年度软带和科创规则分别计算期望交易后市值，再以最低期望仓位合并为单一卖单。这样不会因波动突然上升被迫低位卖出。

### 6. 科创状态采用月度观察事件

状态包含周期、是否激活、高水位、上周期峰值、连续 ON/OFF 月数、待触发原因、上次真实卖出月和上月收益是否低于激活线。预览在内存副本上计算；显式确认月度计划时保存观察，即使当月没有成交。影子模式只保存经确认的观察，不保存模拟成交；正式模式只有真实成交才进入冷静期并关闭当期。该事件边界使重复 GET/POST 预览完全无副作用。

### 7. SQLite 追加式迁移与幂等确认

schema 版本递增，新增 snapshot header/items、strategy state、plan confirmation/fills 表，不修改既有投资记录。确认使用唯一 `idempotency_key`；数据库事务同时保存快照、成交和状态补丁。回滚只需停用新接口/参数，旧报告继续可用；新增表可保留而不影响旧代码。

### 8. 交易成本和单位

成本模型集中配置：佣金率、最低佣金、滑点、各资产交易单位和自愿交易最高成本占比。买入价格向不透支方向加入滑点，卖出价格扣滑点；费用在取整后计算。硬上限与风险卖出忽略小额成本延后，年度自愿再平衡可延后。

### 9. 回测策略适配器和参数锁

回测每月构造与实盘相同快照并调用决策函数，成交模型再把订单转成下一状态。四个变体只通过配置特性开关表达。锁定快照包含所有新增阈值、成本和模式；测试入口在首月比较哈希。敏感性运行输出单独表，不修改锁定配置也不提供“最佳参数”。

## Risks / Trade-offs

- [真实券商成本口径可能不同] → 默认保守成本并允许显式覆盖，报告同时披露毛收益和净收益。
- [账户很小时整手交易导致长期偏离] → 保留权益待投现金和国债一手保护，并在计划中披露不可执行缺口。
- [科创样本和触发次数少] → 预注册参数、影子运行、至少三次独立触发门槛和邻近参数敏感性。
- [双口径容易被误解] → 所有输出并列显示全账户权益/防御比例与受管组合资产/组别权重。
- [确认接口状态复杂] → 唯一幂等键、事务写入、计划哈希和重复预览测试。
- [完整回测与旧基线难以逐点一致] → V1.3 使用兼容特性开关并保留旧指标实现作回归对照。

## Migration Plan

1. 先合并 README 候选准则、配置和新域模型，不改变现有 `/api/report` 默认行为。
2. 迁移 SQLite 新表，加入只读预览；用单元和集成测试验证现金守恒与跨入口一致。
3. 在报告中正式启用三阶段补仓、核心硬上限和年度软带；旧输入仍仅分配。
4. 科创利润保护保持 shadow，完成历史回放和 2026 持续观察。
5. 只有验收及三次独立触发门槛满足后，创建新的参数锁版本将模式显式切为 live。
6. 回滚时关闭新策略开关并恢复旧报告路由；新增表和已确认审计记录不删除。
