## Context

当前需要为一个 6-8 个 ETF 的月度新增资金配置系统实现完整代码。系统分为两条数据流：流A（每月运行，只执行不调参）和流B（离线回测，参数确定与验证）。资产池覆盖价值（白酒、银行、红利、沪深300）、成长（科创50）、防御（国债）三个因子组。

设计文档 ds.v1.2.winner.md 已经过三轮评审，给出了完整的模块分解、因子定义、约束规则和分配算法。本项目直接落地该设计。

## Goals / Non-Goals

**Goals:**
- 实现流A完整链路：数据获取 → 因子计算 → 评分 → 市场温度计 → 风险控制 → 组合约束 → 资金分配 → 月报输出
- 实现流B回测引擎：point-in-time 回放 + 训练/测试期分离验证
- 所有估值分位基于 expanding window，严格防未来函数
- 所有参数集中在 config/ 目录，运行流和回测流共享同一份参数

**Non-Goals:**
- 不实现实盘交易接口（只出配置方案报告，人工执行交易）
- 不做日内或周频决策，仅月度频率
- 不实现 ML/深度学习模型（所有因子为规则驱动）
- 不涉及已有持仓的强制卖出（默认不卖，只配置新钱）
- 不含 V2 的重型 walk-forward 优化

## Decisions

### D1: 两条独立数据流分离

**决策**：流A（每月运行）和流B（回测验证）在代码层面共享核心计算模块，但运行入口和参数管理完全分离。

**理由**：防止回测参数泄漏到实盘运行流。流A从 config/ 读取锁死参数并执行；流B在训练期探索参数空间，锁死后以和流A完全相同的代码路径执行测试期验证。

**替代方案**：合并在一个脚本里用 flag 控制。拒绝——容易误操作。

### D2: 科创50替代机器人ETF

**决策**：用科创50（000688）作为成长因子载体，覆盖半导体、生物医药、新能源等多个科技子行业。

**理由**：机器人ETF本质是主题赌注，行业过于集中。科创50是宽基成长，长期波动更低，更适合作为系统化的成长暴露。

**注意**：科创50权重高度集中于半导体行业（约30-40%），需在资产描述中明确标注。

### D3: Expanding Window 分位计算

**决策**：所有估值分位（PE/PB/股息率）使用 expanding window 计算，窗口上限 5 年。

**理由**：这是防未来函数的根本手段。滚动窗口（rolling window）在每个时点只使用过去 N 年的数据，而 expanding window 使用从数据起点到当前时点的所有数据（上限 5 年）。5年窗口是经验平衡点——太短（3年）分位波动太大，太长（10年）可能跨越结构性变化。

### D4: 市场温度计双指标设计

**决策**：同时使用沪深300 PE 分位和全A等权 PB 分位，双指标一致时才调整投资比例。

**理由**：单一指标可能因指数编制规则变更而失真。双指标减少误判。不一致时维持上一期比例，不行动。

### D5: 资金分配用"缺口分 + 机会分"混合

**决策**：分配优先级 = 0.5 × 缺口分 + 0.5 × 机会分。缺口分衡量当前权重偏离下限的程度，机会分衡量估值吸引力。

**理由**：纯机会分会导致某资产持续超配；纯缺口分会忽略估值。50/50 为默认值，训练期可验证调整。

**特殊情况**：如果所有资产缺口分 ≤ 0（都不缺），跳过缺口调整，直接按机会分分配。

### D6: 平滑惩罚而非硬切断

**决策**：组合约束层使用线性平滑惩罚函数，而非硬性切断。

**规则**：当前权重 < 上限-5% 时可全买；在 [-5%, 0] 区间线性递减到 0；超过上限不可买。

**理由**：硬切断在临界值处产生决策跳变，平滑惩罚让接近上限时逐渐减速，更易解释。

### D7: SQLite 作为存储引擎

**决策**：使用 SQLite，数据表包含 publish_date 字段用于 point-in-time 约束。

**理由**：数据量极小（约 15000 行），SQLite 零运维、单文件、可 Git 备份。publish_date 字段确保回测只能使用在决策日已公开的数据。

### D8: 因子组约束防止伪分散

**决策**：在单资产约束之上增加因子组约束。价值+红利组（白酒+银行+红利+沪深300）上限 60%，成长组（科创50）上限 15%。

**理由**：单资产独立看都合规，但价值类资产在经济下行时一起跌，实际风险高度集中。因子组约束强制分散到不同回报来源。

## Risks / Trade-offs

- **[科创50集中度风险]** 权重高度集中于半导体行业，实际分散效果可能低于预期 → 资产描述中明确标注，监控行业集中度
- **[纯停买修正缓慢]** 不卖出的策略在强上涨趋势中回归很慢 → 年度再平衡作为保险，允许偏离超过10个百分点时卖出
- **[温度计硬阈值]** 硬阈值在临界值附近可能导致决策跳变（如 79% vs 81%） → 目前规则是双指标一致才行动，不一致维持上期，可以减少边缘误判
- **[回填段污染]** 指数回填段（base_date 到 publish_date 之间）的数据带有未来视角 → 回填段数据打标，回测时选择性排除
- **[训练期过拟合]** 训练期参数多可能导致手工过拟合 → 严格样本外纪律：测试期只看不调；测试期效果差时需在新时间段重做验证
- **[AkShare 数据依赖]** 数据源依赖 AkShare 服务可用性和数据质量 → datasource 层封装重试和异常处理；保留手动数据导入路径作为降级方案
